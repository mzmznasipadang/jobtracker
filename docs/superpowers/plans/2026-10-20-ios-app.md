# Native JobTracker iOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a native iOS client with automatic Google authentication and the existing account's live server data.

**Architecture:** Keep business logic in existing server libraries. Add bearer-authenticated JSON routes and a PKCE-protected browser-login handoff, then build SwiftUI screens consuming that API. Existing web server actions continue to use the same services.

**Tech Stack:** Next.js 16.4.2, TypeScript, SQLite, Vitest; Swift 6, SwiftUI, AuthenticationServices, CryptoKit, Security, URLSession, XCTest.

**Spec:** docs/superpowers/specs/2026-10-20-ios-app-design.md

## Global Constraints

- Native project lives in /Users/naspadstudio/Documents/Gitea/JobTrackingiOS; backend lives in VicJobTracking.
- Existing server, Google identity, account approvals and per-account data remain authoritative.
- Mobile exchange codes expire after 60 seconds, are hashed at rest, single-use and bound to S256 PKCE.
- Mobile session tokens use existing 30-day expiry; store them in Keychain and send as Authorization Bearer headers.
- Keep server-side AI, Gmail, PDF generation, usage allowances and archive rules authoritative.
- Read installed node_modules/next/dist/docs guides before backend edits.
- No production deployment or App Store submission is included.
- Use iOS 18 minimum, gate Liquid Glass at iOS 26, Swift 6 with complete concurrency checking and explicit nonisolated module default; UI state uses MainActor.
- New app development bundle ID: id.naspadstudio.JobTracker; no production signing team is inferred.

## Review Focus

- Expired/replayed handoffs, wrong PKCE verifier and parallel login must never issue an unintended session.
- Revocation and overlapping numeric job IDs must never expose another account's data.
- Network loss or expired session during edits must preserve input and offer recovery.
- Stale draft revisions and duplicate submissions must preserve existing saved results.
- Archived/expired documents and background polling must respect access deadlines and screen lifecycle.

Modify src/lib/accounts.ts, src/lib/google-login.ts, src/lib/oauth-state.ts, src/app/api/auth/google/callback/route.ts and tests/google-login.test.ts.
