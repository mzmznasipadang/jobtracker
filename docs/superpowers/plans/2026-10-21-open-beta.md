# Open Beta Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let visitors join the web beta at https://tracker.naspadstudio.id/beta using Google and enter their own tracker.

**Architecture:** Reuse the Google OAuth callback, transactional account registry, sessions, and per-account databases. Gate automatic member registration with a server-only setting. Add a public branded entry page and signed OAuth return context without changing mobile handoff behavior.

**Tech Stack:** Installed Next.js 16.4.2, React, TypeScript, SQLite, Google OAuth, Tailwind, Vitest. No new dependencies.

**Spec:** [Open beta design](../specs/2026-10-21-open-beta-design.md)

## Global Constraints

- Public URL: https://tracker.naspadstudio.id/beta. No invitation codes or waiting list.
- OPEN_BETA_ENABLED=true enables registration; missing or false preserves approved-account login.
- Existing inactive accounts stay inactive. No signup path can grant owner permissions.
- Sign-in scopes remain openid, email, and profile. Connecting Gmail is optional.
- Preserve existing mobile behavior, sessions, safe destinations, per-account data isolation, and AI policy enforcement.
- Use the incumbent Wordmark, Montserrat, theme tokens, navy #272660, and sky #49bce9.
- No automatic welcome emails, new identity providers, or deployment in this implementation.
- Preserve existing uncommitted work, particularly mobile edits in the account registry and OAuth files. Do not reset, overwrite, or commit unrelated changes.
- Before writing product code, read the relevant installed guides in node_modules/next/dist/docs/, including App Router pages, cookies, route handlers, and server/client components. Read applicable authentication and design skills before execution.

## Review Focus

- Existing but inactive email: registration must not restore access (Task 1).
- Reused Google subject with a different email: reject without inserting an orphan member (Task 1).
- Invalid or expired OAuth context: never select an untrusted redirect; fail safely (Task 2).
- Beta closed during sign-in: callback must enforce the current setting (Task 2).
- Signed cookie without a valid session: render the public action rather than granting authenticated entry (Task 3).
