# JobTracker workflow improvements — Phase 2

Date: 2026-10-20
Status: proposed for owner review. Phase 1 live and owner-confirmed.

## Purpose and approved scope

Help each approved user bring existing applications into JobTracker, take their data out, track concrete next actions/interviews, and remember recruiters and conversations. User selected **in-app reminders only**. No reminder email, recruiter outreach, calendar integration or notification permission is implied.

Preserve private account stores, shared owner-controlled AI, Phase 1 draft review, request accounting, and archive/restore with permanent live-data deletion after 30 days. These features work without AI or a Gmail connection and consume no AI allowance.

## Approach and alternatives

Recommended: extend the existing Next.js interface, account-private SQLite stores, server actions/routes and ten-minute worker. Add a Data transfer card to Settings, Tasks and Contacts navigation pages, and related panels on job detail pages. Use additive private-store v4 migrations; no registry schema change unless implementation discovers a concrete requirement.

Alternatives considered: CSV alone is simpler but cannot faithfully round-trip documents/history; ZIP archives are familiar but require file extraction and another archive format/security surface. Provide CSV for spreadsheets and a versioned JSON format for full application portability. Start reminders inside the app as selected; push/email can be a separately approved extension.

## 1. Import and export

### Spreadsheet CSV

Import applications from UTF-8 CSV, accepting BOM and properly quoted commas/newlines. Show a preview with column mapping before any database write. Required mappings: URL, company and job title. Optional: description, status, source, location, applied date, salary minimum/maximum/currency/period and one note. Offer a sample template; reject missing required values rather than invoking extraction automatically. Invalid/unknown status or salary/date formats produce row-level errors. Let the user correct mappings and upload a corrected file; never guess ambiguous date formats.

Canonicalize URLs with the existing helper. Preview identifies duplicates within the file and against active/archived jobs in that account. Default is skip existing jobs; imports never overwrite or automatically restore a job. For archived duplicates, link to the restore flow if still eligible. Expired archives cannot be restored and may be purged before import, making the URL available for a fresh record.

Display accepted/skipped/error counts and a bounded preview before confirmation. Import only the selected valid rows after explicit confirmation; errors remain downloadable as a CSV report. Revalidate duplicates, archive expiry and the preview content on the server at commit time. One transaction per confirmed batch; failure rolls it back. A single-use batch token or payload fingerprint prevents duplicate notes/records on retried submissions. No capture/extraction/check/classification requests or email messages are generated by import. Imported jobs can be reviewed and checked manually afterward.

CSV export includes job/application fields, dates, source, status, salary and archive deadline; notes are optionally included. Quote cells correctly and neutralize spreadsheet formula prefixes in text cells (=, +, -, @, and leading control/whitespace variants) so opening the download does not execute formulas. Maintain valid numeric salary values. Offer all/active/archived scope and an applied-or-created date range. Explain that CSV does not include PDFs, draft structure or full history.

### Portable JSON

Use a documented format identifier and formatVersion:1. Export the user's selected jobs, original posting text, notes/events, saved drafts, generated versions/PDFs and provenance, plus associated tasks and contacts/conversation notes. Include the master CV snapshots embedded in drafts; an optional current master CV is explicit and imported only after a separate replacement confirmation. Portable export preserves provenance as history, but does not expose shared Markdown skill bodies or allow imported provenance to change the server's active model/skills. Include skill filenames/revisions and provider/model only. Older exported snapshots with no bodies remain valid display-only history.

Never export/import OAuth credentials, API keys, login/session identity, account IDs as authority, registry policies, usage billing records, linked mailbox contents or shared administrative configuration. The file contains sensitive personal data and is downloaded only through an authenticated no-store attachment route. It is a portability file, not a deployment/database backup.

JSON import validates the entire document before preview. New private IDs replace file IDs; all relationships must reference validated records in that file. Reject unknown format versions, dangling references, duplicate version identifiers, impossible timestamps and invalid CV/draft structures. Limit editable text/arrays using existing Phase 1 bounds. Imported PDFs must be validly decoded base64 with a PDF signature and size bound; serve only as attachment, never execute uploaded HTML. No filesystem paths or file extraction are used. Imported draft source/provenance is untrusted; bind it to validated master facts, mark its origin as imported, and do not reuse source finalization IDs or allow it to select provider/skills. A subsequent new AI draft uses the current global setup and normal accounting.

Default conflicts are skip, not overwrite or merge. If a job is skipped, its dependent job-specific notes/drafts/versions/tasks/links are also skipped; show this in preview. Reuse an existing contact only on a confirmed exact normalized nonempty email match; blank-email contacts remain separate and a name match alone never merges people. No automatic contact or current-master-CV overwrite.

Preserve archival deadlines. Import must not restart a 30-day clock; already-expired archived records and their dependent job content are rejected. Historical imported events must not be interpreted as new Gmail signals or trigger automatic outreach/AI work.

### Bounds and operational behavior

CSV uploads: maximum 5 MiB and 1,000 application rows per batch. Portable JSON: maximum 50 MiB, 1,000 jobs and 5 MiB per decoded PDF, with a total bounded by the file cap. Enforce byte limits while reading, before parsing; do not trust Content-Length or browser checks. Configure route limits without widening every server-action body limit. Preview/session staging expires after 30 minutes and is private to the initiating account. Do not retain a second plaintext uploaded copy after commit/cancel/expiry.

Use bounded server-side staging in that account's SQLite store rather than trusting submitted preview rows. Reject overlapping import/export work for the same account with a retry message. Build consistent exports from a short read snapshot and bound the completed output before sending headers. If selection exceeds caps, return a helpful error and ask for a narrower date/scope selection; never silently truncate or produce an incomplete successful file. Recheck current account approval and record expiry at download/commit time. Escape preview and report text; no sensitive file contents in logs.

## 2. Tasks and in-app reminders

Tasks have title, optional notes, category (application, follow-up, interview, other), optional job/contact links, optional due date/time, optional reminder time and completion state. Users can create, read, update, complete/reopen and delete their own tasks. Use revision checks to prevent stale edits. Interview tasks can hold a meeting URL/location and round label; keep validation and rendering as plain text/safe links.

The Tasks page offers Today, Upcoming, Overdue, Completed and Unscheduled views. Overview shows a compact Today/Overdue panel and count; job/contact pages show their linked tasks. No separate calendar service is required. Display the next scheduled interview prominently. A reminder appears inside the app at its reminder time and remains until dismissed, snoozed or completed. Dismissing a reminder does not complete its task. Snooze sets a new reminder time; completion clears the active reminder. Reopening resets dismissal and uses the user's saved reminder schedule, immediately visible if already due.

Use Jakarta time (Asia/Jakarta) for entry/display, labeled consistently with the existing app. Store UTC instants. A date-only task is due at the end of its Jakarta day. Timed interview reminders default to 30 minutes before due time; other scheduled tasks default to due time. Users can choose a custom reminder instant or turn it off. Unscheduled tasks have no automatic reminder. Past-due entries become visible immediately. Reject invalid dates and reminder-after-due times unless the user explicitly snoozes a reminder after a missed deadline; preserve the original due time when snoozing.

Due queries are computed from current time on authenticated reads, so worker downtime does not lose reminders. Refresh the visible count/list periodically (60 seconds while the tab is visible) and on page focus; label the timing and do not request browser push permissions. No queue of notifications and no delivery/email table is needed for in-app reminders. The existing worker only handles staging expiry/maintenance; no repeated notification side effects.

Tasks linked to archived jobs are suspended and hidden from active reminder/Today queries. Restore reactivates them with their original deadlines; past due tasks immediately appear overdue. Permanent job deletion cascades linked tasks, including through the 30-day purge. Standalone tasks and contacts are retained. Expired job-linked task detail must not leak content before cleanup. No task may point across account boundaries.

## 3. Recruiter and contact tracking

Contacts have name (required), company, role/title, normalized email, phone, profile URL and notes. Support create/read/update/delete, search by name/company/email and links to one or more jobs. Store in the current user's database only; no shared contact directory or Google Contacts scope.

Contact detail shows linked jobs, user-written conversation notes and linked tasks. A conversation note records timestamp, channel (email, phone, LinkedIn, meeting, other), plain-text summary and optional job link. Do not automatically copy Gmail bodies, send outreach, infer relationships with AI or harvest JobStreet profiles. Existing recruiter email fields can offer an explicit Add contact action that prefills a form; the user confirms before a contact is saved or linked.

Prevent accidental duplicate nonempty emails by offering the existing contact to link/edit rather than silently creating or merging it. Names/emails belong to users' private records; matching across accounts is forbidden. Allow contacts without email. Validate public profile/meeting URLs as http/https and render external links safely. Fields are plain text with bounded lengths: name/company/title ≤300 chars, email ≤254, phone ≤100, URLs ≤2,000, contact/task/conversation notes ≤20,000. Keep searches parameterized and case-insensitive.

Deleting a contact requires confirmation and removes its conversation notes and job links. Linked tasks remain with contact_id cleared; their job link and user-written content stay intact. Permanent job deletion removes job links and job-specific conversation notes but retains the contact and standalone conversation notes. Archived job links remain viewable with deadline labels; new links or job-specific conversation edits are blocked while archived. Expired links and their content are hidden immediately pending purge.

## Data and lifecycle integration

Private v4 migration adds tasks, contacts, job_contacts, contact_conversations and private expiring import batches. Foreign keys and indexes enforce intended cascades. Use ID mapping during JSON import and per-account uniqueness for normalized nonempty contact emails; do not use imported IDs directly. Existing v3 job/draft/archive/billing behavior must remain unchanged. Keep all activity/authorization services scoped by current account. Revoked accounts are excluded from UI access; their expired staged imports are cleaned through maintenance without reactivating them.

Retain historical job provenance as a safe portable summary; do not confuse imported skill names with authorized server skill rows. Keep job status transitions and Gmail classification logic unchanged unless needed to exclude archived/expired task/contact references.

## Verification and release

Test genuine v3→v4 migrations preserving accounts/sessions/keys/CVs/jobs/drafts/PDFs/usage, repeat opens and foreign-key behavior. Test CSV quoting/BOM/formulas/ambiguous dates, malformed/oversized/chunked uploads, duplicates and preview token expiry/replay, JSON round-trip and relationship remapping, foreign/untrusted identifiers, partial conflicts and rollback. Export/import must perform zero AI/Gmail calls and must not alter owner policies.

Test task UTC/Jakarta boundaries, date-only/timed/past-due schedules, snooze/dismiss/complete/reopen, stale edits, archived suspension/restore and exact expiry, visible-tab refresh and downtime recovery. Test recruiter CRUD/search/duplicate handling, contact deletion, job purge cascades, unsafe URL/text rendering and account isolation at services/actions/download routes.

Run full tests, lint/type checks, production Docker build and authenticated disposable mobile browser flows with actual PDF round-trip. No real-user deletion, external mail or paid AI calls for smoke verification. Independently review the release. Build before cutover, stop writers for full matched data/env backup, retain old images and health-gated paired rollback. Verify live data preservation/worker/public health and request owner UI confirmation after deployment.

## Deferred

No automatic recruiter messaging, reminder emails, browser push, Google Calendar/Contacts integration, recurring tasks, team-shared contacts, automatic spreadsheet sync, database-level backup upload or application autofill. These require separate scope decisions. Existing in-app reminders are intentionally not guaranteed to alert users while JobTracker is closed.
